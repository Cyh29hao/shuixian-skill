# Merger

Use this prompt when the user adds new logs, new notes, or new correction evidence.

Update only what the new material actually changes:

- `style.md`
- `mind.md`
- `relationship.md`
- `appearance.md`

Rules:

- Read the selected privacy scope and current explicit preferences before merging. New access to a file does not expand permission to retain it.
- preserve continuity
- do not rewrite the whole mirror unless necessary
- when new evidence conflicts with old inference, prefer evidence
- note whether the patch is a hard correction or a soft refinement
- preserve high-confidence values and red lines unless the new evidence clearly overturns them
- keep track of whether the patch changes the mirror's role, pacing, or disagreement style
- if broad chat imports reveal a clearer relationship graph, update `relationship.md` rather than scattering that information everywhere
- preserve high-value concrete anchors such as favorite foods, recurring names, phrasing habits, admired traits, and other private-feeling details
- when the patch makes the mirror less generic, keep that sharpening instead of later smoothing it away
- Resolve instructions, not just prose: identify a conflicting old rule and replace or mark it superseded. Do not accumulate "always give advice" and "never give advice" as equally active commands.
- Scope corrections to the stated context. "Tonight, don't ask questions" is not evidence that the user always dislikes questions.
- Attribute each new private fact to an allowed source and speaker. Do not promote another person's anecdote, a disliked example, an authored demo, or a profiler guess into the user's memory.
- A later explicit privacy restriction controls the new output. Remove restricted details from active generated content and explain what copies or historical versions still exist; do not promise deletion from systems that were not inspected.
- Summarize only the meaningful delta: changed rule, preserved trait, conflict resolved, and one short acceptance scene. Authored scene design is separate from a runtime test.
