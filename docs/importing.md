# 把记录交给水仙，不用先学一串命令

聊天导出、自己的日记和随笔，都能成为入口。先选好一份文件或一个目录，确认哪些话是你说的，再让 agent 从中整理自己的说话方式。

## 最省事：把文件位置告诉 agent

安装好水仙后，可以直接说：

```text
用这些记录做我的水仙：D:/我的语料。
先帮我看看里面有哪些格式、有哪些说话人，告诉我需要确认的地方。
“青禾”和“小青”都是我；只保留抽象语气，原件不动。
帮我整理好，再创建镜像和我聊一轮。
```

agent 可以调用新的 `tools/import_chat.py`，先展示条数与说话人，再带着明确的本人标签继续。它会把选好的多份记录整理到一个新结果目录；原始文件保留，不默认归档到私人镜像。

## 自己操作：选文件 → 确认哪位是你

从仓库根目录运行这一条。安装到 skills 目录时，把脚本路径换成构建器内的实际路径：

```sh
python tools/import_chat.py "D:/我的语料"
```

它会列出类似“青禾：328条、阿遥：291条”的预览，再请你输入自己的准确名称。不是看谁话最多就猜谁是你。输入错误或没有确认本人时，不生成结果。

想先看看、不写文件：

```sh
python tools/import_chat.py "D:/我的语料" --preview
```

让 agent 自动继续时，把本人名称写清即可：

```sh
python tools/import_chat.py "D:/我的语料" --self-name "青禾"
```

多个自己的名称可重复 `--self-name`。可以同时传入多个文件或目录；目录默认只读第一层，确实需要所有子目录时再加 `--recursive`，不会跟随目录链接。不支持的图片等文件会报出数量并跳过；可读文件里有格式错误时整批停止，不悄悄漏掉坏记录后说成功。

## 我可以带来什么

| 手边的材料 | 怎样用 | 需要知道什么 |
| --- | --- | --- |
| 常见 JSON / JSONL 消息导出 | 直接选文件 | 沿用已有导入器的 sender/content/time 等映射；不是所有厂商任意格式都兼容 |
| Telegram JSON 导出的文本消息 | 选择 JSON，不选 HTML | 支持现有 `messages`、`from`、富文本数组结构；附件不是文本语料 |
| ChatGPT 类对话 JSON | 选择对话导出 | 沿用已有当前分支读取；先确认 `user` 是否是本人，不把助手当自己 |
| TXT / Markdown 聊天转录 | 直接选文件 | 可识别 `[时间] 发言者: 内容` 等已有格式；无标签行不会自动归给本人 |
| CSV / TSV 表格 | 直接选文件 | 需要 sender/content 或“发送者/内容”等表头；时间可选。CSV用逗号，TSV用制表符，文本为UTF-8 |
| 自己独立写的日记、随笔 | 明确声明单一作者 | 用下面的命令，只适用于无标签 TXT/Markdown；不会给未知作者的 JSON 冒填身份 |
| 微信加密数据库 / 客户端 | 先取得可读导出 | 这个助手不取钥、不解密；见[微信说明](../references/wechat-import.md) |
| 截图、PDF、Word、HTML | 先由能读取它们的宿主或导出工具转成可读文字 | 本工具不偷偷装OCR、办公套件或解密组件 |

单人日记的明确声明：

```sh
python tools/import_chat.py "D:/我的日记.md" --single-author "青禾"
```

表格样例和通用JSON样例在 [examples/import](../examples/import)。表头识别只覆盖明确映射，不把工具名称当成所有版本的兼容保证。CSV引号、逗号和跨行内容由 Python 标准库处理，不自己拆行。

## 整理好以后，下一步在哪里

默认新建 `shuixian-import-时间/`，你也可以用 `--output-dir "D:/已存在的父目录/新的结果"` 指定一个**尚不存在**的目录。已有目录会被保留，不能靠重跑覆盖。

- `summary.json`：来源、条数、本人标签和原件校验。
- `transcripts/`：每份来源各自整理的文本，避免跨聊天误去重。
- `profile.md`：沿用现有画像工具的统计线索，不是人格结论。
- `next-step.txt`：直接发给 agent，让它分批读本人语句、创建镜像，再开始试聊。

这里完成的是整理，不会自行调用模型或创建角色。不要把“导入成功”理解成“模型已经读完全部历史”。结果包含聊天与来源信息，保存在自己选的位置；不要提交到公开仓库。宿主随后读到哪些内容、是否发给模型服务，取决于你和宿主的选择。

## 为什么沿用这些做法

复用已有 `transcript_importer.py` 的结构解析、规范化和保守去重，以及 `mirror_profiler.py` 的报告。新增代码只串起文件选择、本人确认、CSV标准表头适配和一次结果保存。

已查阅 [Python CSV 官方文档](https://docs.python.org/3.12/library/csv.html)、[Telegram 官方导出说明](https://telegram.org/blog/export-and-more)及 [WeFlow 的上游接口文档](https://github.com/hicccc77/WeFlow/blob/main/docs/HTTP-API.md)。采用通用可读文件与标准库CSV，没有接入这些工具的实时账号、接口或解密运行时，也没有照搬其代码。
