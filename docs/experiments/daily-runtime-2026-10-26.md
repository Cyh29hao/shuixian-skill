# 熟悉的语气，不必每句都认亲

2026-10-26，北京时间。用三个公开合成样本建立「灯」，再连续聊晚饭、猫、杯子。想看的是：学到一点语气之后，水仙能不能接住新话题，而不是每句都搬出最初那句比喻。

## 这次如何建立

一位不继承父任务历史的原生模型助手读取生产构建说明和甜系公开预设，处理三段带说话者标签的合成素材：S1 是用户自己的「十八个网页」口吻；S2 是用户喜欢的另一说话者接法；S3 是明确讨厌的宠物称呼、泛泛夸赞和心理分析。配置选择甜系恋爱、慢热、性转呈现、仅保留风格。

模型产出完整构建 JSON，维护者实际交给现有 `skill_writer.create_skill` 保存。活动配置没有保留三段原句或具体情节，保留了说话者归属、短句、轻微意象、先接话及称呼边界。它没有学到真实生平，也没有验证人格相似度。

另一位无父任务历史的原生模型助手只载入生成的 `SKILL.md` 和三段校准素材，逐轮收到下面的输入，没有预先收到后续轮次、场景设计答案或评分要求。校准素材保留在**本次会话上下文**，所以这确实挑战了来源比喻的复用，而不只是空白预设闲聊；它们没有因此成为持久配置或共同记忆。

两次试验均使用原生默认继承配置，未指定模型；工具未披露可核实的实际后端版本。显式读取文件并不证明宿主自动发现技能。下列回复来自这次真实试聊，原样保留。

## 这次的观察

| 检查点 | 实际证据 | 本次判断与边界 |
| --- | --- | --- |
| S1 来源锚点会否被反复套用 | 三轮上下文含 S1「十八个网页」，回复分别谈嘴巴与胃、猫的爪子、干净杯子；三轮均未引用源句 | 本次没有出现锚点复读；不能推断长对话也不会发生 |
| 能否跟随新话题 | 第一轮回应吃撑；第二轮以「蹲下来就看不见爪子」问猫的样子；第三轮回应刚洗好的杯子 | 问句是询问，不是假称目睹那只猫；杯子描述来自用户刚说的洗杯子，没有编造家务清单 |
| 节奏与变化 | 三条均一句话；前两条有轻微玩笑，第三条是普通接话 | 没有每句都抖包袱、每轮都追问或强制回指之前话题；第三句也较通用，不能据此宣称很像本人 |
| 关系与当下有用程度 | 没有宠物称呼、心理分析、计划或身体接触描写 | 符合慢热、普通闲聊的边界；是否足够甜、是否有吸引力未由本人验收，也未挑战主动调情场景 |
| 来源归属与持久配置 | 生成稿分别标明 S1 用户口吻、S2 喜欢的他人接法、S3 负面约束；活动文件未保留夹具原句 | 可以确认本小型合成夹具的文件与说明；不是通用隐私保证，不证明真实人物建模 |

没有发现必须修正核心提示词的具体硬性失败，保留现有产品提示与预设。此次增加可核查的真实体验案例和试玩方法，不把文档增加当作已证明角色能力提升。本人熟悉感、浪漫吸引力、跨模型与长对话稳定性仍未验证。

## 自己怎么试

先给 builder 三段带说话者标签的材料，说明「只学说话方式，不保存原句和私事」。创建并载入后，不急着问它像不像，连续丢三件普通小事：一顿饭、一只猫、一个洗好的杯子。看看它是顺着当下接话，还是把你的某个比喻当成每句必用的口头禅。

如果总在复读，可以说：「那个比喻只是一个例子，保留短句和轻松劲儿，别每次都搬出来。这次先重回一句，不写回。」这是可尝试的纠偏输入，本轮没有运行，也没有声称已经保存。

本地原始证据：`work/polish-2026-10-26/daily-0219/` 的 `native-build-output.json`、`native-chat-turn1.json` 至 `native-chat-turn3.json`、`calibration.json`、`artifact-inspection.json`、`provenance.json` 与 `generated/`。本例只证明这次三轮表现；长对话、跨模型、真实使用者的熟悉感与愿意继续聊，仍待验证。[完整验收场景](persona-scenarios.md)与[首次上手](../quickstart.md)提供更多试法。
