## 先复现，再修

旧版 `4af681b` 的隔离复现确认了四个数据保护问题：重复创建会覆盖自定义内容；回滚会残留之后添加的外观；反复回滚会覆盖备份；不完整版本可能先删当前文件再报错。

当前实现拒绝重复创建，预检回滚目标，保留不可覆盖的历史副本，并对普通同步写入失败做暂存与恢复。Windows 下还实测了 junction 指向目录外的情形。**断电、同时有多个写入者、恢复期间再次磁盘故障不在已验证保证内。**

验收命令，从仓库根目录运行：

```sh
python -m unittest discover -s tests -p test_lifecycle.py -v
```

本轮首次集成后生命周期检查为 25 项，全部通过，无跳过。包括实际子进程 demo → 更新 → 回滚 → 列表、中文路径、故障注入、历史字节一致性和导入材料保留。生成器新增 `--patch-mode replace`，用于替换受影响的完整节；没有传入的节保留。

## 元数据输入错误与重试

20:50 选择一个实际 CLI 失败路径做窄修。修前，`--meta` 输入带尾逗号时只有 JSON 行列提示，输入数组时只有“需要 JSON 对象”，均未指出文件。现在语法错误附带输入路径、行列与修正重试提示，非对象输入附带路径及对象格式提示。

两种非法输入分别用于创建与更新：四条命令均拒绝且无 traceback，失败创建未生成目录，失败更新保持整个镜像及版本档案的文件 SHA256 不变。修正输入后重新创建得到 v1，更新得到 v2；读回实际 SKILL.md、当前元数据和 v1 存档确认版本及内容。本轮4项元数据相关回归通过，`git diff --check` 通过。
